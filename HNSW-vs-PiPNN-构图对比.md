```

╠════════════════════════════════════════╦═════════════════════════════════════════════╣

╠════════════════════════════════════════╬═════════════════════════════════════════════╣
║                                        ║                                             ║
║  向量数据: [v0][v1][v2]...[vN]         ║  分区内向量: [v3][v7][v12][v18][v25]       ║

║  step1: 访问 v_entry  ──┐             ║                                             ║

║  step3: 访问 v_8731   ──┤             ║  v7  → [■■■■■■■■■■■■■]  ↓                 ║

## 三、单点插入 vs 批量分区处理

```
┌────────────────────────────────────────────────────────────────────────────────────┐
│                    HNSW: 增量单点插入 (hnswalg.h:1338-1428)                        │
└────────────────────────────────────────────────────────────────────────────────────┘

  插入点 p 的完整流程:

  已有图:  [0]─[23]─[142]─[891]─...
                              ↑
  maxlevel=3, enterpoint=142  │

  ┌─────── Layer 3 (顶层) ───────────────────────────────────────────────────────┐
  │  从 enterpoint 贪心下降，找到最近节点                                         │
  │                                                                               │
  │  ep=142  →dist?→  邻居[891,2341,...]  →找更近→  ep=2341                     │
  │                   (greedy, no beam)                                           │
  └───────────────────────────────────────────────────────────────────────────────┘
           ↓ 继续下降到 Layer 2, 1 ...
  ┌─────── Layer 0 (目标层) ──────────────────────────────────────────────────────┐
  │                                                                               │
  │  BeamSearch(ep=2341, query=p, ef_construction=360):                          │
  │                                                                               │
  │  top_candidates (min-heap, max 360):    candidateSet (max-heap, 未探索):     │
  │  ┌──────────────────────┐              ┌──────────────────────┐              │
  │  │ dist=0.12, id=2341   │              │ id=2341              │              │
  │  │ dist=0.18, id=891    │  ←─────────→ │ id=8731 (neighbor)   │              │
  │  │ dist=0.23, id=8731   │              │ id=23   (neighbor)   │              │
  │  │ ...                  │              │ ...                  │              │
  │  │ (最多360项)           │              └──────────────────────┘              │
  │  └──────────────────────┘                                                    │
  │                                                                               │
  │  终止条件: candidateSet 最近 > top_candidates 最远  (启发式剪枝)              │
  │                                                                               │
  └───────────────────────────────────────────────────────────────────────────────┘
           ↓
  ┌─────── 邻居选择 (hnswalg.h:519-558) ──────────────────────────────────────────┐
  │                                                                               │
  │  getNeighborsByHeuristic2(top_candidates, M=30):                             │
  │                                                                               │
  │  候选排序: [c1=0.12, c2=0.18, c3=0.23, c4=0.25, ...]                        │
  │                                                                               │
  │  选 c1 ✓ (第一个无条件选)                                                    │
  │  选 c2? → dist(c2, c1)=0.05 < dist(p, c2)=0.18 → ✗ 被 c1 遮蔽              │
  │  选 c3? → dist(c3, c1)=0.30 > dist(p, c3)=0.23 → ✓ 方向不同                │
  │  选 c4? → dist(c4, c3)=0.10 < dist(p, c4)=0.25 → ✗ 被 c3 遮蔽              │
  │  ...直到选满 M=30 个                                                          │
  │                                                                               │
  │  关键: 选出的邻居指向不同方向 (方向多样性)                                    │
  └───────────────────────────────────────────────────────────────────────────────┘
           ↓
  双向写入邻接表 → 若邻居已满(M个连接)则再次剪枝 → 完成插入

  时间复杂度(每点): O(M · ef_construction · log(ef_construction))
                    ≈ O(30 × 360 × 8) = ~86,400 ops + 大量随机内存访问
```

## 四、PiPNN 的分区构建流程

```
┌────────────────────────────────────────────────────────────────────────────────────┐
│               PiPNN: 随机球划分 + GEMM + HashPrune                                 │
└────────────────────────────────────────────────────────────────────────────────────┘

Step 1: Randomized Ball Carving (RBC) 多层 Fanout

  全量数据 N 个点
       │
       ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │ 顶层: 随机选 ℓ 个 leader，每点分配给前 k_fanout 个最近 leader   │
  │                                                                  │
  │  leader: ★ ★ ★ ★ ★                                            │
  │                                                                  │
  │  p1 → {★₁, ★₃}    (fanout=2, 分配到2个分区)                    │
  │  p2 → {★₁, ★₂}                                                 │
  │  p3 → {★₂, ★₄}                                                 │
  │  ...                                                             │
  └──────────────────────────────┬──────────────────────────────────┘
                                 │ 递归划分 (直到叶子 ≤ C_max)
                    ┌────────────┼────────────┐
                    ▼            ▼            ▼
              ┌──────────┐ ┌──────────┐ ┌──────────┐
              │ 叶子 L1   │ │ 叶子 L2   │ │ 叶子 L3   │
              │ {p1,p2,p5}│ │ {p1,p3,p6}│ │ {p2,p4,p7}│
              │ (重叠!)   │ │           │ │           │
              └──────────┘ └──────────┘ └──────────┘

  注意: 同一个点可以出现在多个叶子 (重叠划分保证图连通性)


Step 2: 每个叶子内 GEMM 计算 (并行)

  叶子 L1 = {p1, p2, p5}  (向量维度 d=128)

  X = ┌─────────────────┐
      │  p1: [0.1, 0.3, ...]  │  (3 × 128 矩阵)
      │  p2: [0.5, 0.2, ...]  │
      │  p5: [0.8, 0.1, ...]  │
      └─────────────────┘

  D = X · Xᵀ = ┌────────────────────┐
               │ d(p1,p1) d(p1,p2) d(p1,p5) │
               │ d(p2,p1) d(p2,p2) d(p2,p5) │
               │ d(p5,p1) d(p5,p2) d(p5,p5) │
               └────────────────────┘

  ↓ 向量化排序 (Highway 库 SIMD)

  候选边 (双向 k-NN, k=3):
    p1 → [p2(0.12), p5(0.31)]
    p2 → [p1(0.12), p5(0.28)]
    p5 → [p2(0.28), p1(0.31)]
    + 反向边全部加入


Step 3: HashPrune 在线剪枝 (流式，任意顺序)

  对每个点 p 维护预留池 M (大小 ℓ_max=64):

  预留池布局 (每槽 8 bytes):
  ┌──────┬──────┬──────┬──────┬──────┬──────┐
  │ slot0│ slot1│ slot2│ slot3│  ... │slot63│
  │ id:4B│ id:4B│ id:4B│ id:4B│      │ id:4B│
  │hash:2│hash:2│hash:2│hash:2│      │hash:2│
  │dist:2│dist:2│dist:2│dist:2│      │dist:2│
  └──────┴──────┴──────┴──────┴──────┴──────┘

  插入候选 c 到点 p 的预留池:

  1. 计算残差哈希: h_p(c) = hash(c - p)  [m=12 bit]
     (角度相似 → 哈希碰撞)

  2. ┌─ 找到碰撞槽 (同哈希) ──────────────────────────────┐
     │  dist(c, p) < dist(槽中点, p) ?                     │
     │  YES → 替换 (c 更近，同方向选更近的)                │
     │  NO  → 丢弃 (已有更近的同方向候选)                  │
     └─────────────────────────────────────────────────────┘

  3. ┌─ 无碰撞，池未满 ─────────────────────────────────────┐
     │  直接插入新槽                                         │
     └─────────────────────────────────────────────────────┘

  4. ┌─ 无碰撞，池已满 ─────────────────────────────────────┐
     │  dist(c, p) < dist(最远槽点, p) ?                     │
     │  YES → 替换最远槽 (整体更近)                          │
     │  NO  → 丢弃                                           │
     └─────────────────────────────────────────────────────┘

  关键性质: 无论候选以何种顺序插入，最终结果相同 (History-Independent)
  → 完美兼容并行 GEMM 的流式输出!
```

╠════════════════════════════════════════╦═════════════════════════════════════════╣

║  并行粒度: 点级别                 ║  并行粒度: 分区级别 (粒度更粗，锁竞争少)  ║

║  随机访问: 并行加剧 cache 竞争    ║  随机访问: 几乎无 (分区内局部)            ║
╚═══════════════════════════════════╩════════════════════════════════════════════╝
```

## 八、关键性能数字对比

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                        实测性能对比 (10亿向量, 192核)                              │
├─────────────────────┬──────────────────────────┬────────────────────────────────┤
│ 指标                 │ HNSW                     │ PiPNN                          │
├─────────────────────┼──────────────────────────┼────────────────────────────────┤
│ 构建时间 (BigANN)    │ ~180 分钟                │ < 20 分钟  (12.9× 加速)       │
│ 构建时间 (OpenAI)   │ ~160 分钟                │ < 10 分钟  (8-20× 加速)       │
│ IPC                 │ 0.33                     │ 1.26       (3.8× 提升)        │
│ LLC cache miss      │ 高 (~1000次/点)          │ 低 1个数量级                   │
│ 10@10 Recall        │ 高 (基准)                │ 相当 (单副本≈Vamana单pass)    │
│ 内存效率            │ 多层存储开销             │ 更紧凑                         │
│ 查询性能            │ ★★★★★ (多层跳转快)     │ ★★★★ (单层)                  │
├─────────────────────┼──────────────────────────┼────────────────────────────────┤
│ 构建瓶颈            │ Beam Search 随机访问      │ GEMM 计算 (可 GPU/硬件加速)   │
│ 并发扩展性          │ 受锁竞争限制             │ 接近线性扩展                   │
│ 磁盘索引兼容        │ 内存索引                 │ 可生成 DiskANN 格式            │
└─────────────────────┴──────────────────────────┴────────────────────────────────┘

性能差距来源拆解 (PiPNN speedup 12.9× 的来源):

  Multi-level fanout 分区优化:    3.35×
  GEMM + 向量化排序:              27×  (叶子构建内部)
  消除 Beam Search 随机访问:      ~4×  (cache miss 减少)
  ─────────────────────────────────
  综合(乘法效应受制约于 Amdahl):  ~12.9× (最终测量值)
```
